pacpad

A terminal app manager for Arch Linux. One TUI for your repo and AUR packages, and for the webapp and TUI-app launchers you create. Every change it makes is a plain pacman or yay command, shown to you before it runs.

01What it is

pacpad is a single full-screen terminal program for looking after what's installed on an Arch system. It has four tabs:

TabWhat you do there
1 InstalledSee every installed package with version, repo, size and install reason. Filter by explicit, dependencies, orphans or foreign (AUR), sort by name, size or install date, then install, remove, reinstall, re-mark, list files or open the upstream URL.
2 SearchFuzzy-search names and descriptions across every repo in your pacman.conf, then install one or several.
3 AppsList, launch, edit and remove the webapp and TUI-app launchers pacpad created.
4 UpdatesPending-update listing is still being built. For now, press u on the Installed tab for a full system update.

It also works without the TUI: pacpad search, pacpad webapp and pacpad tui are headless subcommands for scripts and .desktop files.

02Why it exists

Keeping an Arch box tidy means remembering a dozen pacman flags, switching to yay for anything from the AUR, and keeping track of the app launchers you've made by hand. pacpad puts that in one place without hiding what's underneath.

Finding orphans, explicitly installed packages or AUR packages means separate pacman -Qdt, -Qe and -Qm runs.

They're filters on one list, with the details pane next to it.

Repo packages go through pacman, AUR packages through your helper, and you have to know which is which.

pacpad checks whether a package is foreign and hands it to yay or paru automatically.

omarchy-style webapp and TUI launchers are easy to create but have no place to browse or remove them later.

The Apps tab lists every launcher pacpad made, and removes it cleanly.

Package TUIs often drop you back to a raw terminal for sudo, conflict prompts or PKGBUILD review.

Those prompts run inside pacpad's own screen, on a terminal it owns.

Tools that link libalpm can break when a pacman update bumps its version.

pacpad reads pacman's database files directly, so it keeps working across those upgrades.

What it deliberately doesn't do: replace pacman, keep its own package state or hide commands from you. Every write is something you could have typed yourself.

pacpad has a read path, a write path and a launcher path. They never share code that touches your system.

Reading packages

pacpad parses /etc/pacman.conf, the local package database and every sync repo database itself, then merges them into one index of what's installed and what each repo offers. Parsing extra.db takes a moment, so the merged index is cached at ~/.cache/pacpad/index.bin. The cache is keyed on each database file's path, modification time and size, so it's rebuilt only after an actual sync.

Changing packages

Every action becomes a planned command: sudo pacman … for repo packages, or your AUR helper when a foreign package is involved. pacpad shows that exact command in a confirm modal. Once you accept, it runs on a pseudo-terminal that pacpad owns, drawn live inside its own window. Because the child process gets a real terminal, sudo's password prompt, pacman's provider and conflict questions and yay's PKGBUILD review all work as normal.

Managing launchers

A webapp is a Chromium-family browser started with --app=<url> and its own window class. A TUI app is a command run in your terminal emulator, floating or tiled. Both are written as .desktop files in ~/.local/share/applications, with a pacpad- filename prefix and an X-PacPad-Managed=true marker. Before deleting anything, pacpad re-reads the file from disk and checks for the marker.

04Safety rules

  1. Nothing runs unseen. Every install, remove, reinstall, mark and update shows the literal command first.
  2. Protected packages need a typed confirmation. Removing pacman, sudo, systemd, glibc, any linux* kernel package, or anything in the base group requires typing REMOVE. Reinstalling or updating them is normal maintenance and isn't blocked.
  3. Clean removal, your choice. Removal defaults to -Rns, which also removes dependencies and config files that are no longer needed. Press r in the modal to switch to -R, which removes only what you selected.
  4. Only its own launchers. pacpad never edits or deletes a .desktop file without its marker.
  5. Dry run. --dry-run prints the command any write would run and runs nothing. That covers launcher writes too, but launching an existing app always works.

05Install

There's no AUR package or prebuilt binary yet, so build from source. You need Rust 1.82 or newer and a recent pacman.

shell
$ git clone https://github.com/ric-v/pacpad
$ cd pacpad
$ cargo build --release
$ install -Dm755 target/release/pacpad ~/.local/bin/pacpad

Then run pacpad. The terminal must be at least 60 columns by 12 rows.

06Usage

CommandDoes
pacpadOpen the TUI.
pacpad search <query>Search installed and repo packages by name or description, and print the top matches. Add --all for every match.
pacpad webapp add <name> <url>Create a webapp launcher. --icon takes a URL or path. Without it, pacpad fetches the site's favicon.
pacpad webapp list | remove <name>List or remove webapp launchers.
pacpad tui add <name> <command>Create a terminal launcher that runs command. Add --float or --tile for the window style, and --icon for a local icon.
pacpad tui list | remove <name>List or remove TUI-app launchers.
--dry-runPrint what any write would run, and run nothing.
--pacman-conf <path>Read a different pacman.conf, for testing against a fixture.
example
$ pacpad webapp add Linear https://linear.app
$ pacpad tui add btop btop --float
$ pacpad --dry-run webapp remove Linear   # see what it would do

08Configuration

Configuration is optional. pacpad detects everything on its own, and a missing or malformed config file is ignored rather than treated as an error.

~/.config/pacpad/config.toml
browser    = "brave"     # binary on $PATH, or an absolute path
terminal   = "ghostty"   # one of the terminals listed below
aur_helper = "paru"      # ignored unless it's installed

09Compatibility

NeedsDetection order
AUR helperconfig, then yay, then paru. With neither, repo packages still work through pacman.
Webapp browserconfig, then your default browser if it's Chromium-based, then Chrome, Chromium, Brave or Vivaldi. Webapps need --app mode, which Firefox doesn't have.
TUI-app terminalconfig, then xdg-terminal-exec, then $TERMINAL, then Ghostty, kitty, WezTerm, Alacritty or foot.
SystemArch Linux or an Arch-based distro with pacman. Built for omarchy-style desktops, but doesn't require one.

11FAQ

Does it replace pacman or yay?
No. It reads pacman's database files to show you what's there. Every change is a plain pacman, yay or paru command that you see before it runs.
Does it need root?
No. pacpad runs as you. Write actions go through sudo pacman or your AUR helper, which asks for your password inside pacpad's screen.
Will it touch launchers I made some other way?
No. It only lists, edits and removes .desktop files carrying its own marker.
Can I try it without changing anything?
Yes. Run pacpad --dry-run. Every write prints its command and waits for a key, without running anything.
