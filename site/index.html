Your whole Arch box, one terminal away.

pacpad is a terminal app manager for Arch Linux. Browse, search and manage repo and AUR packages, and create or remove webapp and TUI-app launchers, all from one ratatui TUI. Every action shows you the literal command before it runs.

01 / Features

One TUI for packages and the apps you launch.

pacpad sits on top of pacman and your AUR helper instead of replacing them. It gives you one place to browse, change and clean up what's on your system.

01

Four tabs, one screen

Installed lists your packages by default, Search fuzzy-matches across every configured repo, Apps shows pacpad's own launchers and Updates is one key away.

02

Every package action

Install, remove, reinstall, mark explicit or as a dependency, update the system, list files and open the upstream URL, with multi-select on space.

03

AUR-aware

Detects yay or paru and hands foreign packages to it automatically. A helper set in your config is respected, as long as it's actually installed.

04

No terminal handover

Transactions run on a pseudo-terminal pacpad owns, rendered live in its own screen. sudo prompts, pacman's conflict questions and yay's PKGBUILD review all still work.

05

Webapp & TUI launchers

Turn a URL into a Chrome app-mode window, or a command into a terminal app with its own .desktop entry. Then list and remove them again from the Apps tab.

06

Survives pacman upgrades

pacpad parses the pacman database directly instead of linking libalpm, so a pacman release that bumps the library's soname doesn't break it.

02 / Safety

See the command. Then decide.

pacpad never runs anything you haven't seen. Every write goes through a confirm modal that prints the exact argv it's about to execute.

  • The literal command, every time. Install, remove, mark and update all show the real pacman or yay invocation first.
  • Protected packages need a typed confirmation. Removing pacman, sudo, systemd, glibc, any linux* kernel package or anything in the base group means typing REMOVE, not pressing a key.
  • Only its own launchers. The Apps tab lists and removes the .desktop entries pacpad created, and never touches anyone else's.
  • A dry run for everything. --dry-run prints what any write would run and runs nothing.

03 / Install

Build it in three steps.

You need a Rust toolchain (1.82 or newer, edition 2021) and a recent pacman. That's it.

  1. Get the source

    Clone the repository from GitHub.

    $ git clone https://github.com/ric-v/pacpad && cd pacpad

  2. Build a release binary

    Thin LTO and a stripped binary are already set in Cargo.toml.

    $ cargo build --release

  3. Put it on your PATH and launch

    Copy the binary somewhere on your $PATH, then run pacpad.

    $ install -Dm755 target/release/pacpad ~/.local/bin/pacpad && pacpad
ComingAn AUR PKGBUILD, CI and prebuilt release binaries are still to come. Until then, building from source is the way in.
04 / Usage

A TUI first, scriptable when you need it.

With no arguments pacpad opens the TUI. Every subcommand is a headless escape hatch, so it stays scriptable and .desktop files can call it directly.

shell 
pacpad                          # launch the TUI
pacpad search ripgrep           # headless search
pacpad search rust --all        # every match

pacpad webapp add Linear https://linear.app
pacpad webapp list
pacpad webapp remove Linear

pacpad tui add btop btop --float # or --tile
pacpad tui list

pacpad --dry-run webapp add Docs https://wiki.archlinux.org
# prints the command, runs nothing
~/.config/pacpad/config.toml 
# Entirely optional. Every field falls back to
# auto-detection, and a missing or malformed
# file is never fatal.

# A binary on $PATH, or an absolute path.
browser    = "brave"

# One of the terminals pacpad knows about.
terminal   = "ghostty"

# Ignored unless it's actually installed.
aur_helper = "paru"

06 / FAQ

Questions, answered.

Does pacpad replace pacman or yay?

No. pacpad reads the pacman database to show you what's there, and every change it makes is a plain pacman, yay or paru command that it shows you first. Your existing tools stay in charge.

Do I have to leave pacpad to type my sudo password?

No. Transactions run on a pseudo-terminal that pacpad owns and draws inside its own screen, so sudo's password prompt, pacman's provider and conflict prompts and yay's PKGBUILD review all work right there.

Will it touch my other .desktop files?

No. The Apps tab only lists and removes the launchers pacpad itself created. Anything else in your applications folder is left alone.

Can I try it without changing anything?

Yes. Run pacpad --dry-run and every install, remove, mark, update and launcher write prints the command it would run and waits for a keypress, without running anything. Launching an existing app is never blocked.

What's the minimum terminal size?

pacpad needs at least 60 columns by 12 rows. Anything smaller and it asks you to make the window bigger.

Is there an AUR package?

Not yet. An AUR PKGBUILD, CI and release binaries are on the roadmap. For now, build it with cargo build --release.
